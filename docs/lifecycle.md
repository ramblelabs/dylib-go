# Raw object initialization and cleanup

`Load` stages raw objects. The first successful `Link`, `Lookup`, `Resolve`, or `Bind` relocates the selected objects, validates all lifecycle entries and requested roots, applies W^X protection, then runs their initializers. Repeated linking does not run them again. A failed validation runs no native initializer and permits a dependency fix and retry after rollback cleanup succeeds.

If cleanup of an unpublished image fails, the link error includes both the original failure and the cleanup failure. The session retains that image, its libraries and provider leases, publishes no callable image, and rejects further linking or mutation with the stored error. Call `Close` to retry resource cleanup. This also applies when requested-root validation or unwind registration fails, or concurrent retirement prevents publication. No static finalizers run for an image that never began initialization.

`Close` prevents further calls, releases prepared call plans, executes session-owned exit callbacks, runs termination arrays, drains any callbacks registered by those terminators, unregisters optional runtime function tables, retires [native/emulated TLS](tls.md) values, and only then frees the image and native registration storage. OS library handles remain available throughout this sequence and are released afterward. `DefineSymbol` provider leases remain alive through both image and library cleanup, including failed-initializer exit callbacks; see [retained dependencies](dependencies.md). `KeepLibraries` retains OS handles, but does not retain the raw object image or skip its finalization. A native cleanup error keeps unfinished image/library storage and provider leases alive while the session remains retired. Call `Close` again to retry; exit callbacks and static finalizers that already completed do not repeat. Closing a session that never began initialization runs no object code; repeated close is harmless.

## Supported tables

| Format | Initialization | Termination | Order |
| --- | --- | --- | --- |
| ELF32/ELF64 | `SHT_PREINIT_ARRAY`, `SHT_INIT_ARRAY` | `SHT_FINI_ARRAY` | Preinitializers first; numeric suffix priorities ascending, default 65535; finalizers reverse |
| ELF AMD64/ARM64/i386 split CRT | Executable `.init` fragments | Executable `.fini` fragments | Join in original input/member order; `.init` after preinit and before init tables; `.fini` after fini tables |
| ELF32/ELF64 legacy | `.ctors`, `.ctors.NNNNN` | `.dtors`, `.dtors.NNNNN` | Priority is `65535 - NNNNN`, default 65535; constructors reverse each table, destructors retain forward entry order |
| Mach-O64 | `S_MOD_INIT_FUNC_POINTERS`, linker-resolved `S_INIT_FUNC_OFFSETS` | `S_MOD_TERM_FUNC_POINTERS` | Pointer tables before offset tables within each object; entries forward; terminators reverse |
| COFF AMD64/ARM64/i386 | `.CRT$XI*` `int(void)` tables, then `.CRT$XC*` void tables | `.CRT$XP*`, `.CRT$XT*` void terminator tables | XI before XC; lexicographic subsection order; XP before XT, both forward |

Equal-priority initialization uses provider-before-consumer object order derived from retained relocation dependencies. Strongly connected components preserve input order. Finalization reverses that object order on ELF/Mach-O. Modern arrays retain initialization entry order and reverse finalization entry order; legacy ELF uses the entry directions above within each input table. Explicit ELF priorities and COFF names take precedence over dependency order; dependency cycles do not imply a language-specific solution to cyclic global initialization.

Legacy tables require `SHT_PROGBITS` pointer storage. Their normalized priorities are merged with modern arrays: preinitializers run first, constructors run in ascending priority, and destructors run in descending priority. Legacy `0` and all-bits-one (`-1`) entries are ignored. Count-prefixed GNU linker sets are not supported; a count is rejected as a non-code pointer. Similar ordinary section names such as `.ctors_data` are not lifecycle tables. These rules apply to raw input tables, without reproducing a complete executable's CRT section concatenation or process startup.

Only selected archive members participate. COMDAT-discarded arrays and their references do not participate. ELF numeric priorities must fit 16 bits. Pointer tables must contain whole native pointers, cannot request executable storage, and may contain null sentinels. Every non-null entry must point into an executable section of this image; ARM64 entries must also be instruction aligned. External initializer pointers are currently rejected. The validated entry lists are copied before initialization, so later writes to a writable table cannot substitute a finalizer.

Mach-O offset tables contain whole read-only, non-executable, four-byte-aligned `uint32` entries with no relocations. Each entry is relative to the original `__TEXT` segment's preferred address, or zero when that segment is absent, as in ordinary `MH_OBJECT` files. `Link` maps the original address to an unambiguous retained executable section in the same input object, then normalizes it to the private image's base. Independent code pages cannot be rebased with a uniform Mach-O slide. Offset zero is a valid initializer, not a null sentinel. Overflow, discarded/missing code, overlapping original ranges, non-code targets and unaligned ARM64 instructions fail before any initializer runs. Unselected archive members do not undergo this address validation. Within each object, pointer initializers precede offsets even if the offset section appeared first; provider-before-consumer ordering still applies between objects.

## ELF executable startup fragments

On Linux AMD64, ARM64, and i386, selected read-only executable `SHT_PROGBITS` `.init` and `.fini` sections are joined into one function per name. Stage the CRT prologue (`crti.o`), body objects or archives, and CRT epilogue (`crtn.o`) in that order. Archive members keep their original file/member positions even when symbol resolution discovers them later. Only selected members participate; root an otherwise unreferenced member explicitly with `Link`.

Each group occupies contiguous RX pages. Alignment gaps contain architecture-specific NOP instructions so execution falls through from prologue to body to epilogue. Ordinary section relocation still applies, including references between fragments. `_init` or `_fini` must begin the first retained fragment. The loader checks the standard GNU split CRT frame: AMD64 reserves eight stack bytes, i386 saves EBX and reserves eight bytes, and ARM64 saves/restores X29/X30. CET landing pads and ARM64 NOP, BTI, and paired PAC signing/authentication forms are accepted. This is a conservative completeness check for these CRT conventions, not general instruction verification; arbitrary standalone `.init`/`.fini` function frames are outside this contract.

The complete `_init` runs after preinitializers and before modern or legacy constructor tables. The complete `_fini` runs after reversed termination tables. Both share the image lifetime and execute once. Missing entries/epilogues, writable or non-PROGBITS fragments, excessive alignment, and incompatible frames fail before initialization; missing dependencies can be staged and linking retried. `Inspect` can describe an individual fragment, while execution requires a complete selected group.

This does not supply process startup, CRT TLS tables, or arbitrary runtime services. Optional Windows/Linux/macOS C [unwind registration](unwind.md) is owned through initialization and cleanup.

## Integer initialization failures

COFF `.CRT$XI*` entries use the native C ABI (`cdecl` on i386), skip null entries, and must return zero for success. A nonzero result stops the XI sequence before later entries or XC constructors execute. The operation returns `*InitializationError` with `Object`, `Section`, byte `Offset`, and signed C `Code`; `errors.Is(err, ErrInitialization)` identifies this failure.

An executed initializer can already have changed native state, so this failure is permanent for that session. No image or symbol is published. `Load`, `Define`, `Link`, `Lookup`, `Resolve`, and `Bind` return the stored error without executing initialization again. Validation errors before native execution remain retryable.

The failed mapping and library references remain owned until `Close`: completed XI entries may have registered exit functions pointing into that mapping. `Close` retires the session, drains those registrations outside its mutex, skips static termination tables for incomplete initialization, and then releases code and libraries. Reentrant cleanup lookups return `ErrClosed`. Callers must close a failed session and stop any native activity it started; cleanup cannot undo arbitrary native side effects. A new session can make an independent attempt.

## Initialization callbacks and concurrent close

Native initialization and OS library opening run without the session mutex. Reentrant or concurrent `Load`, `Define`, `DefineSymbol`, `Link`, `Lookup`, `Resolve`, and `Bind` return `ErrInitializing` while this phase is active; retry after the initiating operation returns. No ordinary symbol, lease, or bound function is published before raw initialization succeeds.

`Session.WithInitializingAddress(name, use)` provides explicit, temporary access during this phase. For raw objects, selected symbols have passed relocation, lifecycle validation, W^X protection, and optional unwind registration. Native global state can still be partially initialized: the adapter must know which values are ready and use the correct signature. The scope does not select additional archive members. Nested calls are allowed, and each scope retains code and library dependencies until its callback returns.

During `Load` of an OS library, including DLL loading from an import archive, only previously retained libraries, explicit definitions, and optional process symbols are searched. The opening handle is unavailable until the OS loader returns. OS symbol lookup runs outside the session mutex; callers must still respect the OS loader's own locking and constructor restrictions. In particular, [Windows DLL constructors](https://learn.microsoft.com/en-us/windows/win32/dlls/dllmain) must not wait for newly created threads: their startup waits for DLL initialization to finish, including llgo's host-thread-backed goroutines. Outside an active initialization phase the method returns `ErrNotInitializing`; after an initialization failure it returns the stored error, and after retirement it returns `ErrClosed`.

All address use must finish before the scope callback returns. Do not retain the temporary address or close the same session from its initializer or scope. Native data synchronization and external threads remain the caller's responsibility. Concurrent `Close` retires the session immediately and waits for both initialization and active scopes; new calls fail with `ErrClosed`. A successful native initializer or library open still completes its ownership handoff and cleanup, while the initiating operation returns `ErrClosed`. Failed XI images remain owned through active scopes and exit-registration cleanup.

## C and C++ exit registrations

Undefined raw-object references to `atexit`, `__cxa_atexit`, `__cxa_finalize`, and `__dso_handle` use image-owned implementations. These names, including their `__imp_` forms, are reserved against `Session.Define`. An object's own definitions retain normal linker precedence; bringing a custom runtime implementation makes its lifetime the caller's responsibility. OS libraries retain their own runtime and registration rules.

The implementation preserves arguments and DSO tags for `__cxa_atexit`. The implicit `__dso_handle` stores its own address in a read-only slot adjacent to the image, so direct PC-relative or ARM64 page references do not depend on native heap placement. `__cxa_finalize(tag)` consumes matching registrations; a null tag consumes all registrations in this image, not other sessions. Plain `atexit` callbacks and tagged registrations share a LIFO list. An entry is detached before invocation, so recursive finalization cannot invoke it twice. New registrations during finalization are visited. This supports ordinary global C++ construction and destruction without registering object code in the process-global exit list. It does not adapt C++ methods, exceptions or RTTI. Thread-owned registrations use the separate [native/emulated TLS runtime](tls.md).

Go owns parsing, dependency ordering, table validation, native thunk encoding, and session lifetime. A small C bridge owns the native list, synchronizes native registrations, and invokes native function pointers. Context-bound thunks are implemented for SysV/Windows AMD64, AArch64, and i386 cdecl. The i386 thunk realigns the helper's stack for GNU C even when its MSVC caller supplies only four-byte alignment. No Go closure, Go pointer, or ambient thread-local session state is used. libffi is not required for initialization or cleanup; these paths run with both ordinary Go/cgo and llgo.

This is image cleanup, not arbitrary rollback of native effects or hot module replacement. Void initializers and destructors have no Go error channel; XI entries provide only their integer status. They must return normally. Initializers use the explicit scoped API above for reentry. Finalizers run after retirement without the session mutex; session lookups/calls return `ErrClosed`. Finalizers must not close their own session, which would wait for the ongoing cleanup itself. Native code may start threads or publish raw addresses; callers must stop such activity before closing. `Close` cannot infer whether an external runtime still holds a code pointer. Mixed termination tables and registered callbacks use the sequence above, rather than promising every platform CRT's process-exit interleaving.

## Verification

The existing setup-go and setup-llgo native jobs execute C/C++ fixtures that verify dependency order in either load order, archive extraction without unused constructors, global destructors, late registrations, per-DSO and recursive termination, session isolation, explicit table order, idempotence, and validation failure before initialization. Linux amd64/arm64 Go and llgo and Linux 386 Go also execute Clang `-fno-use-init-array` output, legacy sentinels and entry directions, mixed modern/legacy priorities, dependency retry, archive selection, and invalid-finalizer rejection before any constructor executes. The observer is a separately retained OS library, so finalizer effects are checked after the raw mapping has been freed. Pure Go tests inspect lifecycle sections for all eight target formats and reject malformed or unsupported forms, including legacy ELF32/ELF64 tables.

Windows native jobs execute real `.CRT$XI*` tables for amd64/arm64 Go and llgo and i386 Go. Tests verify XI/XC name and phase ordering, null boundaries, positive/negative errors, no repeated execution or publication, registered-exit cleanup without static terminators, dependency/root retry, and rejection of invalid entries before any initializer runs. POSIX native jobs exercise the common integer-call and failed-session ownership machinery through a private test table; production ELF/Mach-O parsing does not treat ordinary arrays as integer initializers. libffi jobs verify that failed-image cleanup callbacks can reenter Go and the retired session without deadlock.

macOS amd64/arm64 Go and llgo jobs also execute offset-table fixtures at `-O0` and `-O2` through objects and archives. The tests compact genuine Clang pointer tables into ld64's linker-synthesized offset encoding; LLVM's assembler has no spelling for this section type. Actual C initializer bodies verify offset zero, mixed pointer/offset order, dependency/root retry, one-time execution and termination after close. C++ fixtures check provider ordering with either table type, exit registrations and lazy extraction despite an invalid offset in an unused member. Pure Go tests cover both target formats, nonzero preferred bases, independent code-section placement and malformed tables; native tests reject invalid offsets before even the valid pointer initializer runs.

The libffi jobs also execute constructor callbacks through raw objects, archives, and OS libraries on eight Go and six llgo targets. Windows jobs additionally exercise constructor reentry and concurrent close when `Link` opens a DLL from a GNU import archive. Tests cover nested Go/C entries using scoped raw symbols, prior library/retained provider resolution, rejection of ordinary operations before publication, successful calls after publication, close during raw/library initialization, and active scopes surviving XI failure until cleanup. libffi supplies the test callbacks; the initialization/scoped lifetime implementation does not require it. Pure Go tests verify scope validation, nested adapter errors, panic cleanup, and phase/retirement errors.
